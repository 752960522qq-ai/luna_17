## 新玩法

绿色标记是炮弹首次碰撞的弹道预估落点；橙色标记是瞄准附近敌机时，结合当前速度、飞行方向、弹速和重力求出的射击提前点。目标消失、击落或不可达时清除预瞄。

物理弹道载具使用当前弹种的实际初速及 9.81 m/s² 重力；原版/模板弹道使用原游戏 0.23 速度缩放及炮弹池当前重力。预览不污染真实炮弹的物理配置记录。轨迹在 Unity 主线程计算，最多预览 3000 m、120 s，10 Hz 更新；HUD 在 Android 线程读取数值快照。

伤害先计算 `P有效=P0·max(0,cosθ)^n`，再判定击穿。θ 相对装甲法线，AP/APHE 的 n=1、APCR=1.4、HEAT=0.8。击穿后的动能伤害为 `K·(d/100)²·M·clamp(P有效/装甲厚度,1,1.5)`；M 为 AP/APHE=1、APCR=0.7、HEAT=0.8。AP 的 155 g 装药按 APHE 增伤项 `1+0.25√(0.155/0.1)` 处理，APCR 无装药。

HE 使用 `K_HE·(装药克数/100)^0.6·(d/100)^0.5·B`，击穿时 B=1，否则 B=0.10。每个车型、弹种分别提供装药量；缺失时保留原游戏伤害。HE 碰撞也计算实际入射角。厚度沿用游戏当前受击分区的数据；原有包不具备独立顶甲/底甲参数。爆炸弹、地雷、机枪和烟雾不套用此坦克主炮公式，在线模式保留原游戏计算。

`features.json` 的 K=20、K_HE=10 是本次可调整的初始平衡值，尚未经过真机战斗校准。原游戏扣血接口使用字节，结果四舍五入并限制在 0–255，避免大口径伤害溢出；未击穿动能弹不扣血。新公式不将伤害转成装甲厚度损耗。

## 自行火炮预设与操作

类型 `self-propelled-artillery` 写入运行数据尾部 kind=3，采用原版 SU_85 的履带/限射界控制器。默认左右射界 ±15°、仰角 70°、俯角 5°、炮转速 8°/s、物理弹道、无同轴机枪。

模型需要 `Hull → GunMount → Gun → Barrel_Recoil` 层级；GunMount 为空转轴，固定战斗室网格绑定 Hull。可在构建器点击「自行火炮预设」，或执行：

```bash
python -m tankbuilder project artillery-preset /path/to/project
python -m hatch /path/to/project --output vehicle.hatch
```

自行火炮打开原有5倍镜进入鸟瞰。点击目标位置后，固定目标世界坐标，自动请求炮管方向和俯仰角。单指拖动平移、双指缩放或平移镜头，不改变已选目标。原有射界限制仍有效，超出射界的目标显示橙色。

俯瞰显示实际炮管弹道落点、根据游戏炮口角散布估算的范围，以及最大 3000 m 的平地射程示意圈。散布和射程圈是估算；不把超出当前火炮射界的请求中心标成实际命中点。

## 通用扩展机制

原 `HatchModule` API-2 不变；新增可选 `HatchFeatureHost`。玩法包声明 `type=gameplay`、API-1、能力列表及 `features.json` 内容哈希。数据模组与车型包共用确定性的依赖排序和精确版本匹配，拒绝缺失依赖、版本冲突、循环及重复 ID。旧车型未声明版本时按 1.0 处理。

首批能力为 `ballistic-preview-v1`、`damage-formula-v1`、`artillery-sight-v1`。互不重叠的玩法能力可组合，同一能力的多个提供者会报告冲突；旧前置缺少新接口时报告明确错误。增加新能力时只需扩展前置的能力实现和配置处理器，加载器的解包、校验和依赖流程可以复用。这是针对已适配游戏的扩展入口，不宣称能自动适配任意游戏或任意原生钩子。

```bash
  --android-jar /path/to/android.jar --r8 /path/to/d8.jar \

```

这些验证不替代 Android/Unity 真机测试。本轮尚未实测触摸手感、GPU/HUD 对齐、复杂地形落点和战斗平衡。
