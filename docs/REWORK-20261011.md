# 蟋蟀、装药、成员语音和防空炮镜修复（未打包 APK）

## 定位依据

- 上传蟋蟀 `weapon.json`：AP 数量/穿深为 0，HE 15、HEAT 3、WP 2；原换车就绪检查却要求 AP 穿深和 Launcher.attackPower **大于** 0，最终以 -7 超时保留旧车并关闭新车。修正为非负，初速/炮口/弹药/机枪引用仍须有效。
- 视频显示换车期间有抬升/翻转；源代码确实把两个仍开启碰撞的 Rigidbody 载具生成在同一位置，并等待至少两帧。隔离新车碰撞直到交接，旧车退场后恢复各碰撞体原始 enabled 状态，交接位置跟随旧车当前坐标。此风险修复尚需实机确认与视频现象的对应关系。
- 防空炮镜 SightType 2 被 `<=1` 条件排除；允许地面相机模式下 0/1/2，继续排除飞机、船舶等视角。
- AircraftControl 可由脚本移动 Transform；只读 Rigidbody 速度会丢失运动。增加逐帧位置差分，首样本允许实际刚体速度作为回退，并拒绝时间倒退、停顿和瞬移样本。
- AudioManager.PlayRadioVoice / PlayRadioReply 的 5.1.0 ARM64 入口已核对原始指令及 enum，加入启动指纹检查，保持非启用/在线场景原路径。

## 实现

逐车配置覆盖 84 个原版地面预制体及已知模组入口；未证实的装药显式为 null，保留原计算。旧坦克包读取 weapon.json；新包清单携带独立装药字段。蟋蟀 HE 8300 克、HEAT 2400 克来自上传包。

成员体验单独数据包保存原始 641 WAV，外包和内包均检查大小、摘要、文件名与 WAV 标识；新语音播放使用全句锁，目标类型/时钟/距离片段属于同一句。

保留前一轮未完成工作：弹匣坦克通过 Unity 自己的多点触摸及开火按钮矩形触发原 ButtonFire(0)；炮弹池耗尽时扩充池而不抢占仍在飞行的弹体。

## 已验证与限制

Python 玩法/语音包、逐弹装药打包、载具制作/绑定、原上传包校验通过；C 伤害/运动拦截、触摸连射、零 AP 就绪、碰撞交接及并发语音锁通过；生产 Java 语音播放器通过媒体/调度边界模拟，验证整句片段顺序、忙时丢弃、错误/退出释放；加载器和 Java 模块使用 Android 35 API 编译通过，native C 全量语法检查通过。

此轮没有运行 Android 实机、构建 ARM64 模块或组装 APK。视频问题是否完全消除、防空预瞄实际投影和新语音中文内容/听感，仍需更新构建后的实机回归；不把桌面测试写成实机已验证。

额外全套项目测试中，3 项因仓库未提供/未恢复 T54 原模型 GLB 而不能执行；对应的新装药编译/打包路径已用小型完整载具夹具通过，不把缺少资源的项目测试算为通过。真实 JVM/JNI 双类加载器回归 6 项通过，包含全部新 native 方法注册及签名。
