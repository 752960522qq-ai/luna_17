# 更好的坦克体验：逐车装药配置

编辑 `features.json` 的 `ammunition`。每个车型单独列出 AP / HE / APCR / WP / HEAT，单位全部为**克**，范围 0–100000。

- 原版清单来自用户提供的 5.1.0 游戏资源，共 84 个地面载具玩家预制体，包含防空炮和牵引火炮。
- `null` = 未设置，读取模组自己的装药参数；仍没有参数时保留游戏原伤害。原版资源没有炸药质量字段，因此这里没有编造历史数值。
- `0` = 明确设置为无爆炸装药，区别于 `null`。APCR 的伤害不加炸药奖励，WP 保留原游戏效果。
- 蟋蟀使用上传包 `weapon.json` 的数值：AP 0、HE 8300、APCR 0、WP 0、HEAT 2400。这里记录的是弹头装药，不是发射药。
- 已为 T54_1949、Matilda_III、Panzer_II_Ausf_L、T30 留出逐弹种入口。

例如：

```json
"Grille": {"AP": 0, "HE": 8300, "APCR": 0, "WP": 0, "HEAT": 2400}
```

原版车辆使用预制体名称（例如 `T34_85_Player`）；模组车辆使用 `.hatch` 的 ID。增加任何模组 ID 即可覆盖该车的独立装药，不需要修改 C 代码。配置中明确的数字优先于模组自身参数；`null` 则继承模组参数。

坦克制作项目的 `weapon.json` 也支持在每个 `shells` 项中使用 `explosiveMassGrams` 或 `explosiveMassKg`。两者同时存在时必须一致。打包器把质量写入清单，加载器还能从旧 `.hatch` 的 `weapon.json` 读取，兼容已有蟋蟀包。

AP：装药影响击穿后的爆炸奖励；HE：质量影响爆炸伤害；HEAT：击穿后按本弹装药计算伤害。没有可靠质量的弹药保留原游戏计算，包括原版 HE 的爆炸分类。

修改配置后重新构建/导入玩法 `.hatch`，进入战斗前加载。此目录的打包不生成 APK。

## 合并版本 0.1

更好的成员体验已并入本包。内置 APK 会忽略旧 `better_crew_experience` 包，避免重复占用语音能力。语音从准备、敌人发现、射击实际结果、受击、胜利、击杀及切换弹种触发；旧 RadioVoice 的编号仅被屏蔽，不能直接映射为坦克状态。整段目标/车型/钟点/距离播完前丢弃新事件，不排队。

事件槽：0 准备，1 目标信息，2 未命中，3 伤害≥10，4 被击中，5 胜利，6 击杀，7 伤害<10，12–16 AP/HE/APCR/WP/HEAT 切弹。音频素材保持上传内容，可在 `crew.events` 中替换片段。本次以本地语音识别核对录音：有效伤害使用“重创目标”，轻伤/未击穿槽使用“命中”，击杀使用“目标摧毁”。素材未提供已确认的“没打穿”专用台词，未命中暂用落点偏低的纠偏提示；事件逻辑已区分，但这两个槽的台词仍需补齐准确录音。

制作器提供“主炮允许按住连发”开关，对应 `weapon.json` 的 `continuousFire: true/false`。新项目默认关闭，二号坦克启用。打包清单保存 `continuous_fire`；旧弹匣包没有此字段时保留连发行为。连发仍通过游戏的装填、弹匣间隔、剩余弹药和暂停检查。

构建合并包必须提供原始上传的 `--voice-archive 中系新语音.zip`。完整发布 APK 内置本包和所有已内置坦克，升级只替换已知旧发布字节，保留用户自行修改的包。
