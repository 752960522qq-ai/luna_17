# Offline campaign runtime (Attack on Tank 5.1.0)

The title buttons activate one named request. The companion uses the already running Unity player's Android Looper and the project's scripting adapter to set and read back game mode, player/hostile nationality, unit slot, and stage on the live manager, then loads scene 22 or 23. Selecting a side never changes saved campaign progression. Each scene contains its own inactive factory and an active-self source player, independent of the battlefield placeholder disabled by the stock generator.

In a local campaign, scaled time bounds repeated panic to 2.5 s and a temporary gunner interruption to 5 s, with a two-second recovery window. HP, crew deaths, track repair, towed vehicles, destroyed vehicles and other modes retain their original rules. Combat captions and radio messages are noninteractive. The original core native library, voice pack, ballistics and suspension implementation are delivered unchanged. T-26 belts keep the authored 80-shoe vertex layout and per-instance writable buffers.

The mission's serialized stock TimedEvent components activate five German reserves after 90 s and two Soviet T-34s after 150 s. The enemy aircraft uses the original field's intact aircraft controller, ordnance, affiliation and sighting components: Ju 87 for the Soviet perspective (78 s), Il-2 for the German perspective (135 s). The final objective activates with the T-34s to prevent the first wave from incorrectly ending the battle. Pause, replay and faction switching reuse per-scene timers. The APK requires the Java classes, native companion and updated core module from the same release. The Android runtime build is in `scripts/build_campaign_runtime.py`.

The F uses the stock main gun button for holds and short taps in offline play. A nonvisual UGUI relay keeps a tap until the next Unity frame; the saved stock callback is restored when the player changes tanks. A round enters the ten-shot cycle only after a projectile becomes active or both the reserve and the native loading cycle confirm an immediately resolved shot. An unmatched single-round debit is restored after the pending request times out. Delay and reload use game time, so pausing does not refill the clip. The mission dispatcher uses the stock GameUiManager message sink; it does not create a second text overlay.

To reproduce the cumulative release, run the repository's Python commands with the repository root on `PYTHONPATH`. Run `scripts/prepare_gameplay_refit.py --help` for the preceding complete APK, matching kit and working paths; then use `scripts/build_gameplay_refit.py --help` for the NDK, SDK and project signing inputs. All original Unity archive members are checked after lossless compaction. The engine and the released native core are carried through unmodified.
